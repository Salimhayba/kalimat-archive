## البنية

كل الملفات **في نفس المستوى، بدون أي مجلدات فرعية** — عمدًا، لأن الرفع من الموبايل عبر واجهة GitHub الويب بيسطّح أي مجلدات فرعية تلقائيًا (بيحط كل حاجة في الجذر). فبدل ما نحارب السلوك ده، صمّمنا المشروع كله يتوقعه من الأساس.

```
kalimat-archive/
├── index.html            الواجهة كاملة (HTML+CSS+JS في ملف واحد)
├── manifest.json          بيانات PWA
├── service-worker.js      التخزين المؤقت للعمل بلا إنترنت
├── icon-192.png
├── icon-512.png
├── icon-512-maskable.png
├── apple-touch-icon.png
├── meta.json               إحصاءات عامة + قائمة السنوات المتاحة
├── 2012.json               بيانات سنة ٢٠١٢
├── 2014.json
├── ...
├── 2026.json
├── split-data.js           أداة لإعادة توليد ملفات .json من ملف بيانات مُصدَّر
└── README.md
```

## لماذا البيانات مقسّمة حسب السنة؟

كانت البيانات كلها في ملف واحد (`data.js`، ~٧ ميجابايت). تقسيمها لملفات سنوية بيدّي فايدتين:

- **تحميل متوازٍ أسرع**: المتصفح بيحمّل عدة ملفات صغيرة بدل ملف ضخم واحد.
- **كاش أذكى**: لو عدّلت بيانات سنة واحدة بس، باقي السنوات ما بتتلغيش من كاش المستخدمين — بس السنة اللي اتغيّرت.

**⚠️ نتيجة مهمة لهذا التصميم:** التطبيق دلوقتي **لازم يتفتح من خادم فعلي** (زي GitHub Pages)، ومش هيشتغل بفتح `index.html` مباشرة من القرص (`file://`) — لأن المتصفحات بتمنع `fetch()` من العمل مع ملفات محلية لأسباب أمنية. لو فتحته محليًا هتشوف رسالة توضيحية بدل صفحة فاضية.

بعد أول زيارة عبر الإنترنت، الـ Service Worker بيخزّن كل حاجة، والتطبيق بيشتغل أوفلاين طبيعي بعد كده (تثبيته كتطبيق على الشاشة الرئيسية زي أي PWA).

## النشر على GitHub Pages

1. ارفع **كل الملفات** (الـ٢٢ ملف، بلا أي مجلدات) في جذر المستودع مباشرة — نفس الطريقة اللي بترفع بيها عادةً من الموبايل.
2. من إعدادات المستودع → Pages → اختر الفرع (`main` عادة) والمجلد (`/root`).
3. بعد ما ينشر، افتح الرابط وتأكد إن الأرشيف بيظهر واستخدم "إضافة إلى الشاشة الرئيسية" من متصفح الموبايل لتثبيته كتطبيق.

**تحقّق سريع بعد الرفع:** افتح رابط الموقع + `/meta.json` مباشرة في المتصفح (مثلاً `https://اسمك.github.io/kalimat-archive/meta.json`) — المفروض يطلعلك نص JSON صغير، مش صفحة 404. لو طلعت 404، يبقى فيه ملف مكانه غلط أو الاسم مختلف عن المتوقَّع.


## تحديث الكاش بعد أي تعديل

كل ما تعدّل `index.html` أو أي ملف تحت `data/`، لازم تزوّد رقم الإصدار في أول `service-worker.js`:

```js
const CACHE_VERSION = 'kalimat-archive-v8'; // زوّد الرقم
```

من غير كده، المستخدمين اللي فاتحين نسخة قديمة مخزّنة أوفلاين مش هيوصلهم التحديث.

## إضافة مواد جديدة أو تعديل البيانات

### عن طريق الواجهة (الأسهل)

1. زرار **استيراد** يقبل ملفات JSON بصيغة تصدير فيسبوك، وبيتعامل مع التكرار تلقائيًا (بيتجاهل أي منشور موجود بالفعل بناءً على وقت النشر).
2. لوحة **مراجعة التصنيف** (زرار ✓) بتسمح بمراجعة وتصحيح تصنيف/نوع أي مادة يدويًا، والقرارات بتتحفظ في المتصفح فورًا.
3. زرار **تصدير** بيحمّل ملف `data-export.json` فيه كل البيانات مجمّعة (الأصلية + المستوردة + مراجعات التصنيف).

### تحديث ملفات .json من التصدير

بعد ما تصدّر `data-export.json` من الواجهة، وتنزّل `split-data.js` (موجود أصلًا في المستودع) بجانبه:

```bash
node split-data.js data-export.json
```

الأمر ده بيعيد توليد كل ملفات `<year>.json` و`meta.json` تلقائيًا حسب السنة، في نفس المجلد، جاهزة للرفع على GitHub. الأداة مبنية بـ Node العادي بدون أي حزم خارجية.

## المميزات الرئيسية

- **بحث عربي متقدّم**: يتجاهل التشكيل ويوحّد أشكال الألف/الياء/التاء المربوطة، ويشمل النص والوسوم معًا.
- **فلاتر**: نوع (شعر/نثر/صورة)، قسم، سنة، مؤلف (١٦٩+ مؤلف مستخرَج آليًا مع مراجعة يدوية)، مفضّلة.
- **إخفاء المكرر**: يعلّم التكرار النصي الحقيقي (مش سلاسل الصور) بدون حذف أي شيء فعليًا من البيانات.
- **رحلتي مع الكلمة**: عرض إحصائي لكل سنة (نسب الشعر/النثر، أبرز الأقسام).
- **مراجعة التصنيف**: واجهة مخصّصة لتصحيح تصنيف/نوع أي مادة يدويًا، بأولوية تبدأ بقسم "عام" ثم "حب وغزل".
- **كلمة اليوم**: اختيار ثابت لكل يوم تقويمي (نفس الاختيار لو فتحت الصفحة عدة مرات في نفس اليوم).
- **في مثل هذا اليوم**: يعرض كل ما أُضيف في نفس تاريخ اليوم عبر السنوات المختلفة.
- **PWA كامل**: يعمل أوفلاين بعد أول زيارة، قابل للتثبيت كتطبيق، وضع ليلي/نهاري.
- **وضع القراءة**: فتح أي مادة في عرض مركّز (نص أكبر، بلا تشتيت)، مع تنقّل بالسابق/التالي داخل نتائج البحث الحالية، ودعم أسهم لوحة المفاتيح.
- **وضع القصيدة**: تباعد أسطر أوسع للشعر خصوصًا داخل وضع القراءة، للحفاظ على الإيقاع البصري للأبيات.
- **نظام النجوم**: تقييم شخصي (٠-٥) لكل مادة من داخل وضع القراءة، محفوظ محليًا.
- **الأرشيف بالأرقام**: لوحة إحصاءات كاملة — الإجمالي، توزيع الأنواع، أعلى ١٠ مؤلفين، كل الأقسام، والنشاط سنة بسنة كرسم بياني أفقي — كل رقم قابل للنقر لفتح النتائج المطابقة له مباشرة.
- **الطباعة**: تنسيق مخصّص للطباعة كدفتر أنيق.

## قيود معروفة / تحسينات مؤجّلة

- فهرسة بحث مسبقة (search index) — الحجم الحالي (٨ آلاف مادة) سريع بما يكفي بدون هذا التعقيد؛ يستحق إعادة النظر لو تجاوز الأرشيف ٢٠-٣٠ ألف مادة.
- Virtualized rendering لقائمة النتائج — التصفّح بالصفحات (٢٥ مادة كل مرة) بيحدّ من العدد المعروض فعليًا، فمش أولوية حاليًا.
- صفحة تفصيلية مستقلة لكل مادة (رابط ثابت مثل `/k/6511`) — حاليًا فيه دعم لروابط عميقة عبر `#id=` بدل صفحات منفصلة.
